# MONO — 家計簿

## 1.9：tabiのデザインに統一

tabi（tour-plunnner）の紺 #173b61・生成り #f3f0e9・細い枠線を参照し、ホーム、予算、履歴、設定、出張、入力ダイアログに適用。Yomogi／Caveatを同梱・オフライン保存。数字は読みやすい標準書体を維持。前版の下寄せ／自動余白を解除し、グループ直下から入力欄を配置。2グループなら2等分し、空の3枠目を作りません。既存の保存形式やtabi側のコードは変更しません。

## 1.8：iPhone向けの一画面入力

ホームの項目・金額・登録ボタン・4列3段テンキーを同じ画面に固定。その他の項目は金額の横から選択します。グループ枠は等幅・44px高。左右スワイプで隣のグループに切替（端では停止）でき、タップ操作も維持します。4グループ以上は選択メニューも表示。入力中の金額と項目はグループ別に画面を開いている間保持します。画面端・縦方向・フォーム操作はスワイプ対象外。iPhoneのセーフエリアと可視画面高に合わせ、短い画面ではブランド行を省略します。実機表示は未検証です。

## 1.7：色とアイコン、手書き風の文字、横長テンキー

入力項目・予算一覧に、保存済みの項目色とSVGアイコンを表示します。選択中は色付きの枠とチェックで表示。日本語ラベルに同梱のZen Kurenaidoを使用し、金額は数字用書体を維持。アイボリー・墨色・控えめな真鍮色のデザインです。ホームと詳細入力のテンキーは最大340px幅・44px高・数字20pxに変更。不要なキャッチコピーは復活させていません。

## 1.6：フラットなデザインと小型テンキー

白・黒・グレーを中心に変更。テンキーは横幅最大228px、数字18px、枠と塗りを廃止（タップ領域は44px以上）。見出し13px、ロゴ12px。カードの角丸・影・装飾色を削減。キャッチコピーや英字の飾り見出しを削除し、必要な項目名・金額・操作ラベルを中心に表示します。直接入力・10項目の予算一覧・保存形式は維持。

## 1.5：ホームから直接記録・予算全項目を一覧

ホームはテンキーと項目選択を常設。「入力」を押さず、金額・項目・記録だけで登録できます。日付は今日・支出が初期値。日付やメモは詳細から変更可能です。予算は全項目を2列の一覧にし、自動ページ分割の対象外にしました。初期10項目は2列×5段で、予算額・残額・使用バーを表示。編集画面は「編集」から開きます。見出しは15px、英字の飾り見出しと装飾イラストを表示しません。

## 1.4：画像の初期予算と新デザイン

画像の予算を10項目・合計250,000円として登録します。生活費75,000／自由費50,000／自由費（家族）11,660／燃料費15,000／自動車費11,800／通勤費6,000／積立投資10,000／財形貯蓄10,000／定期貯金50,000／通信費10,540円。支出実績は取り込みません。

初回の1.4起動時、プライベートグループ（存在しない場合は選択中グループ）の当月予算が未登録なら自動保存します。既存の予算は上書きしません。予算画面の「画像の25万円予算を使う」から確認後に置換できます。金額・総額・項目を編集して「変更を保存」。再起動しても編集内容を維持します。別の月へ自動登録はしません。

この予算は固定費・貯蓄を含む手動の総額予算であり、給与実績や15%の貯蓄目標を自動適用しません。給与からの提案は別モードで維持しています。データの保存先・CSV形式・URLは変更していません。

手書きフォント中心の外観を廃止し、システム書体・白/チャコール・ブルーのモダンなUIと新しいベクター図案に変更。固定画面・ページ切替・フェード・ダークモードを維持しています。追加ファイル：`preset.js`（予算初期化）、`visuals.js`（新図案）、`tests/preset.test.mjs`。

さっと記録、ゆっくり暮らす。スマホで使う、オフラインの家計簿PWAです。

1.3ではスクロールを廃止し、画面・入力フォームを表示領域の高さに合わせたページに分けます。下部の「前へ／次へ」は固定位置で、値を保持したままページを切り替えます。画面切替は移動を伴わない480msのフェード。ホームの「アドバイス」では前月より増えた支出を自動計算します。今月は前月の同日まで、過去月は月全体を比較します。新たに4種のオリジナルSVGイラストを同梱しています。

HTML / CSS / JavaScriptだけで動作します。サーバーへの収支送信・アカウント登録・ランタイム外部ライブラリはありません。IndexedDBに保存し、アプリと日本語フォントはService Workerでオフライン保存します。

## 起動

静的HTTPサーバーまたはHTTPSの静的ホスティングから開いてください。`file://`でHTMLを直接開く方法では、Service WorkerとES Modulesが利用できません。

ローカルで試す場合：

```bash
python3 -m http.server 8080
```

`http://localhost:8080/` を開きます。これは静的ファイルの配信だけで、収支を保存するバックエンドではありません。

配信フォルダを生成する場合：

```bash
node scripts/build.mjs
```

生成された `dist/` 全体を配信します。GitHub Pagesでは、リポジトリの **Settings → Pages → Deploy from a branch → main / (root)** を選ぶだけでも配信できます。サブディレクトリに置けるよう、すべて相対URLです。公開先の設定・利用可否はGitHub側の状態に依存します。

PWAの更新時は `sw.js` の `VERSION` も変更します。利用中の画面を突然切り替えず、利用者が「更新する」を押してから反映します。

## 使い方

1. 上のタブで「プライベート」「家族」などを選びます。
2. 中央の＋から、金額を入れ、項目を選び、「記録する」を押します。
3. 日付・メモ・出張の指定が必要なときだけ、追加欄を開きます。
4. 予算画面では、前月の給与がなければ初月の収入目安を入力。標準配分の案が表示されます。
5. 設定で全データをJSONまたはCSVにバックアップできます。

ホーム画面への追加：iPhoneではSafariの共有メニュー、Android/PCでは対応ブラウザのインストールメニューを使います。最初はオンラインで読み込みを完了し、設定の「オフラインで使う準備ができました」を確認してください。

## データモデル

IDはUUID。月別予算のみ `groupId:YYYY-MM` をキーにします。金額は日本円の整数です。

| 保存先       | 主なフィールド                                                                                                                       |
| ------------ | ------------------------------------------------------------------------------------------------------------------------------------ |
| groups       | id, name, color, order, savingRate, tripMode(net/full), dailyRate, lodgingRate                                                                  |
| categories   | id, groupId, name, type(expense/income), bucket(fixed/free/saving), role(salary/other), icon, color, order, weight, hidden, archived |
| transactions | id, groupId, categoryId, type, amount, date, memo, tripId, advance, settled, createdAt                                               |
| trips        | id, groupId, name, destination, departure, returnDate, dailyRate, lodgingRate, amountOverride, createdAt                                        |
| budgets      | id, groupId, month, salary, fixed, savingRate, savingGoal, limit, shortfall, allocations, hasHistory, createdAt                      |
| settings     | id(app), theme, activeGroup, revision                                                                                                |

泊数は日付差から毎回導出します。支給額は `amountOverride ?? ((泊数+1)×dailyRate + 泊数×lodgingRate)`。計算した支給額・差額を独立した取引として保存しないため、編集しても自動仕訳が重複しません。

保存・復元は全ストアを1つのIndexedDBトランザクションで更新します。別タブの変更はrevisionで検出し、古い状態からの上書きを拒否します。削除済みカテゴリは履歴や予算で使われていれば論理削除し、過去の項目名を維持します。

## バックアップ

- JSON：全グループ・設定を含む完全バックアップ。
- CSV：種類別レコードを1行ずつ保存する独自の全データ形式。`name_or_memo`, `date`, `amount`は表計算で参照可能。`payload`列のJSONに全フィールドを保持します。
- 復元できるCSVは本アプリから出力した形式です。表計算アプリがID・payload・日付を変換したファイルは復元できない場合があります。一般的な銀行CSVの取り込みには対応しません。
- 復元は既存データの全置換です。検証と件数確認を行ってから適用します。
- バックアップは平文です。ブラウザのデータ削除や機種変更では記録が失われるため、手元に保存してください。
- 保存元が異なるURL・ブラウザ・端末ではデータは別です。必要ならバックアップで移してください。

## 開発用検証

アプリの実行にnpmは不要です。以下の依存関係はテスト専用です。

```bash
npm ci
npm run check
npm run build
```

`fake-indexeddb`で保存、`linkedom`でDOM操作、Node標準テストで集計・復元・Service Workerを検証します。ブラウザ実機のレイアウト・スワイプやFPSを検証したことにはなりません。

フォント：Zen Kurenaido / SIL Open Font License（`assets/fonts/OFL.txt`）。フォント本体を同梱し、外部CDNには接続しません。

データ形式v2では、旧v1のJSON/CSVとIndexedDBを自動移行します。従来の泊数単価は宿泊日当に引き継ぎ、日当は0円とするため旧出張の支給額は変わりません。
